# 异步分析接口性能实测

日期：2026-10-19。本页面发布经过脱敏的测量口径和耗时样本，不公开服务器地址、用户标识、会话 Token、视频原文或运行日志。

## 真实业务任务

使用合法验收账号及已有 12 秒英语测试视频文件，单独上传后提交唯一目标，固定 GENERAL 模式。经过真实 RocketMQ 消费者、Planner / Executor / Critic，结果 Checkpoint 持久化并查询到 COMPLETED，最终 Critic 通过。

| 阶段 | 耗时 |
|---|---:|
| 上传 91,706 字节视频并返回 | 89.73 ms |
| POST /analysis/ai，HTTP 202 | 95.57 ms |
| 提交至观察到任务完成 | 24.659 s |
| 服务端 AgentLoop | 24.213 s |

本次调用 LLM 5 次，执行 2 轮。复用了相同视频内容的 ASR/OCR 上下文，模型已驻留 GPU；不是冷视频预处理测试。终态通过 500 ms 间隔轮询观察，24.659 s 含排队和观察误差，不是精确的纯消费者执行耗时。

## 低成本隔离提交测量

使用同一生产 JAR 的原始 Controller、认证、归属校验、Checkpoint 查询、Dispatch、幂等、限流、生产者和事件发布；独立测试 HTTP 进程、MySQL schema、Redis 容器及 RocketMQ Topic/Group。MySQL 实例和 MQ Broker 与原环境共享，不能称为完全独立的硬件。

下游消费者仅确认收到消息，不调用模型、不写分析结果。基础服务未 Mock，但这部分仅验证提交接口，不是 50 个真实 AI 任务 E2E。

并发 1，6 个隔离账号轮换，每次请求开始间隔至少 2.2 秒，保留每用户 5/min、全局 30/min 的真实限流。预热 6 次，正式 50 次；随机 run ID 与递增 goal 避免结果、Plan 缓存和幂等重复。200 缓存命中、409 重复、429 限流会使脚本停止，不计为快速成功。

| 指标 | 正式样本 |
|---|---:|
| 平均 | 21.3292 ms |
| P50 | 20.0482 ms |
| P95 | 34.0282 ms |
| 最小 | 17.3691 ms |
| 最大 | 40.7458 ms |
| HTTP 202 且业务码为 0 | 50/50，100% |

56 条含预热的消息全部收到；4 个 MQ 队列各生产、消费 14 条，积压为 0。隔离数据库分析 Checkpoint、Memory Job、Memory 和失败任务记录均为 0，未把收件消费者当作完成了 AI 分析。

[逐次原始耗时 CSV](benchmarks/async-submit-20261019.csv) 保留全部 56 行及预热标志，仅去掉用户、媒体、目标摘要和精确时间等不必要标识。正式样本使用 nearest-rank 百分位：排序后 ceil(p*N)，P50/P95 为第 25/48 个值。成功率分母为全部正式尝试，延迟统计为成功的 202 响应。

客户端位于服务器本机，使用 requests.Session 复用连接和 perf_counter_ns 测完整 HTTP 响应；不含登录、上传、前端代理、浏览器或外网延迟。运行环境为双路 Xeon E5-2630 v3、32 逻辑线程、约 62 GiB 内存、JDK 21、Spring Boot 3.5.9 / Undertow、MySQL 8、Redis 7.4、RocketMQ 5.3.4，两张 GTX 1080 8 GB；真实任务使用本地 Qwen2.5 7B。隔离 JVM 为 -Xms128m -Xmx512m。

6 次预热约为 91.90、25.88、27.77、26.79、27.44、25.19 ms。清理并重建环境的独立无预热收件检查为 96.80 ms；不计入正式 50 次。不能只引用 21 ms 而隐去预热与低负载条件。

未建立同等业务条件下的同步版本对照，不报告“优化前 60 秒”、加速倍数或推理速度提升。测量结果不代表高并发容量、长视频冷预处理、故障恢复或大量真实 AI 任务完成率。202 仅表示已受理，后台成功必须另查终态。
